# Giant fight lag investigation — October 3, 2026

Fixed client issues found while investigating a report of both choppy visuals and delayed actions:

- Movement interpolation started each received route from the last rendered position, without accounting for time since that frame. This re-queued already elapsed travel on successive updates. Advance the previous confirmed route to packet-processing time before preserving any unfinished corners. A regression with packets arriving 20 ms after frames failed before the fix and now stays on schedule across ten updates.
- Every avatar subscribed to the entire local player row and every world tick. Subscribe to attack eligibility and protection boundaries instead, and pass stable building/plot state through the avatar memo boundary. Keep regional protection checks ticking so timed claims still expire correctly.
- Resource reservations were parsed separately by each avatar. Parse each resource row once, share the reservation index, and subscribe each avatar only to its own reservation. Also invalidate table snapshots only once per transaction.
- Ground-click assistance cast all 17 sample rays through terrain and scenery. Collect clickable subtrees once and cast against those while preserving the sample order and overlapping-target behavior.
- A giant first mounted during a wind-up showed a completed warning immediately. Initialize warning timing on mount and when the wind-up deadline changes, including when a recovery update was skipped.

## Runtime check

Isolated local SpacetimeDB at loopback port 4311, database `berigame-giant-perf`; local Vite client on port 4313. Expansion enabled, 12 SDK combatants around the giant, plus one browser observer. Only local fixtures received increased health and an extended raid.

- 30-second server sample: 153 hit events, 50 tick intervals; median 599.6 ms, p95 612.6 ms, maximum 615.9 ms. Intended tick period remains 600 ms.
- Fresh-loaded Chrome client, 5-second frame sample during the fight: 300 frames, average 16.67 ms, p95 17.5 ms, maximum 18.7 ms. About 84 draw calls and 215k triangles at DPR 1.
- An additional 5-second Chrome 4x CPU-throttle sample delivered 300 frames, p95 18.4 ms, no intervals over 33.5 ms. CPU throttling was reset afterward.
- Ground movement through the giant's “Walk here” menu reached the selected tile and cleared the movement target.
- Fresh reload had no browser errors; one existing non-indexed geometry warning. In-progress hook edits caused temporary Vite hot-reload hook-order errors before the clean reload.

These are local development measurements, not production latency, GPU execution time, mobile-device results, or a before/after FPS comparison. The live user session was no longer open when profiling began. No production data or combat cadence was changed.
